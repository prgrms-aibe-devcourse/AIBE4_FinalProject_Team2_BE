# Logging Policy

## 1. 목적
운영 중 발생하는 에러를 수집하고, 유사 이슈를 그룹핑하여 관리자 관제 기능에 활용한다.

## 2. 로그 저장 구조
- `error_log`: 개별 에러 원본 로그 저장
- `error_issue`: fingerprint 기반 그룹핑 이슈 저장

## 3. 보관 정책
- `error_log`: 30일 보관
- `error_issue`: 장기 보관

## 4. 정리 배치 정책
- 오래된 `error_log`는 매일 새벽 4시에 정리한다.
- 삭제 기준: 발생 시각(`occurred_at`) 기준 30일 초과 로그

## 5. 운영 기준
- 원본 로그(`error_log`)는 단기 보관 대상이다.
- 그룹핑 이슈(`error_issue`)는 관리자 관제 및 통계성 분석을 위해 장기 보관한다.
